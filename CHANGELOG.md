# Changelog

Формат на основе [Keep a Changelog](https://keepachangelog.com/ru/1.0.0/),
версии по [Semantic Versioning](https://semver.org/lang/ru/).

## [0.4.0]

### Добавлено

- Модуль «Домены»: добавление, верификация владения через TXT-запись, привязка к учебной странице; TLS через Caddy on-demand (`ask`-эндпоинт) при Caddy-деплое
- Полноэкранный редактор учебной страницы с предпросмотром (desktop/mobile) и переключением
- Граббер: локальное сохранение CSS/JS/картинок/шрифтов — страница не зависит от исходного сайта
- Почта: повторные попытки отправки (до 3 с экспоненциальной задержкой), переход на другой активный SMTP при исчерпании повторов, персонализация по department/position/customFields
- Полноэкранный мастер создания кампании (7 шагов)
- Сотрудники: массовая деактивация и массовое обновление полей, экспорт в CSV, выбор строк
- Интерактивный обзор: карточки-показатели ведут на отфильтрованные списки
- Единая отчётность во всех 10 разделах: предпросмотр, CSV и XLSX, фоновый статус, история отчётов
- Документ `docs/FUNCTIONAL_GAP_MATRIX.md` (матрица полноты) и `docs/TESTING_REPORT.md` (проверки по чек-листу)

### Изменено

- Интерфейс: поля, выпадающие списки и вкладки выровнены по шкале отступов и тап-целям 44px; широкий диалог шаблонов

### Исправлено

- Вкладки рендерились колонкой вместо ряда; продуктовый баг, затрагивавший все экраны с вкладками
- Экспорт CSV кампании, скриншоты учебных страниц и отчёты возвращали 401: обычные ссылки не передавали JWT (теперь загрузка через авторизованный клиент)
- Массовая деактивация сотрудников перехватывалась маршрутом `:id/deactivate`
- Лимит повторов очереди отправки не применялся к уже созданной очереди
- Процент на кольцевой диаграмме кампании мог превышать 100%
- Подпись карточки «Скомпрометировано» обрезалась; сетка метрик кампании оставляла одну карточку в отдельной строке
- Тап-зона ссылки «Назад»; паддинги кнопок вне шкалы; latent-баги Separator и dropdown

## [0.3.0]

### Добавлено

- Граббер страниц: клонирование произвольного URL в HTML учебной страницы
  через headless-рендер (работает для SPA/JS-форм), с автоматическим
  переписыванием `action`/`method` формы. Опциональная функция (тот же
  `screenshot-service`, профиль `docker compose --profile screenshots`)
- Захват значений учебных форм (явный opt-in за конкретную страницу,
  по умолчанию выключено) — для установки факта реальной компрометации,
  не только факта отправки формы. Шифрование отдельным от `APP_MASTER_KEY`
  ключом (`CREDENTIAL_ENCRYPTION_KEY`), дедупликация по хешу значения
  (без повторов одинаковых вариантов), расшифровка только ADMIN-ролью с
  обязательной записью в журнал на каждый факт просмотра
- Детальная история сотрудника для отчёта руководителю
  (`/reports/employees/:id/detail`): что совершено/не совершено по каждой
  кампании, точный IP и User-Agent каждого действия, уникальные варианты
  введённого пароля (без значений — только по хешу, для реального значения
  отдельный explicit reveal)
- Метрика "скомпрометировано" на главной панели — уникальные сотрудники,
  реально введшие данные формы (считается один раз на человека, не на
  попытку)
- Экран обновления системы из веб-интерфейса (Настройки → Обновление):
  текущая и доступная версия, статус помощника обновлений (root-helper),
  запуск проверки/резервной копии/обновления с подтверждением, прогресс-бар
  с текущим этапом, построчный журнал в реальном времени, итог последнего
  обновления по категориям, история прошлых попыток. `install.sh` ставит
  systemd-службу и таймер новым этапом `root_helper`

### Изменено

- Решение о значениях форм пересмотрено по явному запросу владельца
  продукта — полный разбор компромисса, обоснование и границы защиты см.
  [docs/SECURITY.md](docs/SECURITY.md#история-решения-о-значениях-форм-пересмотрено-в-v030)
- Решение о клонировании сторонних сайтов пересмотрено аналогично — см.
  [docs/SECURITY.md](docs/SECURITY.md#граббер-страниц-клонирование-форм-для-учебных-страниц)

### Исправлено

Найдено полным визуальным/функциональным UX-аудитом (все пункты
проверены живым браузером на тестовом стенде):

- Критичный баг компонента `Tabs`: содержимое вкладки вставало сбоку от
  списка вкладок вместо того, чтобы идти под ним — на вкладке
  "Клонировать по адресу" (граббер страниц) это делало функцию полностью
  неработоспособной через интерфейс (поле URL сжималось до 22px). Ломало
  вид вкладок Настроек, Кампаний, Отчётов, Сотрудников
- Тот же класс бага (незарегистрированные Tailwind-варианты
  `data-horizontal`/`data-vertical`) в компоненте `Separator` — latent,
  пока нигде не используется, починено заранее
- Процент на кольцевой диаграмме кампании мог превышать 100% (клики или
  отправки формы могут быть чаще, чем число получателей) и портил
  отрисовку кольца — ограничено 100%
- Сетка метрик кампании: 6 карточек на 5 колонках оставляли одну карточку
  одиноко висеть в новой строке — сетка приведена к 3 колонкам
- Отступы кнопок (`px-2.5`/`gap-1.5` = 10px/6px) не входили в принятую
  шкалу 4·8·12·16·24·32·48·64 — заменены на ближайшие значения по шкале
- Тап-цель ссылки "Назад к сотрудникам" (20px по высоте, меньше минимума
  44px) увеличена без сдвига текста
- Длинная подпись карточки дашборда "Ввели пароль (скомпрометировано)"
  визуально обрезалась при переносе на 2 строки — сокращена до
  "Скомпрометировано"
- `data-inset={false}` в выпадающих меню рендерился React как буквальный
  атрибут и совпадал с CSS presence-селектором как `true` — latent,
  сейчас нигде не вызывается с этим параметром, починено заранее
- Таблицы без визуальной подсказки о горизонтальной прокрутке на узких
  экранах — добавлена тень у прокручиваемого края

## [0.2.0]

### Добавлено

- Вложенные группы сотрудников (родитель/потомок) с рекурсивным подсчётом
  участников — таргетинг кампании на родительскую группу охватывает все
  вложенные подгруппы
- Таргетинг кампании по результатам прошлой кампании (сегмент): получатели —
  те, кто открыл письмо / перешёл по ссылке / отправил форму / не открыл
  письмо в указанной кампании, без ручного экспорта-импорта CSV
- Таргетинг кампании случайной выборкой N сотрудников (опционально из
  группы) — для пилотного запуска шаблона перед массовой рассылкой
- Дополнительные настраиваемые поля сотрудников (текст/число/да-нет/список
  значений) с валидацией типов — для персонализации писем и точного
  таргетинга по HR-атрибутам
- Новое событие «Сотрудник сообщил о фишинге» — положительная метрика,
  ссылка в письме через `{{reportPhishingUrl}}`, работает без JS
- Ручная очистка устаревших записей журнала (события кампаний, журнал
  действий администраторов) с предпросмотром количества перед удалением
- Раздельный экспорт CSV по кампании: журнал событий и сводка по сотрудникам
- График динамики событий на главной панели — диапазон по умолчанию от
  первой кампании, честное сообщение вместо пустого графика, если данных
  ещё нет
- Кольцевые индикаторы метрик на странице кампании
- Кнопки быстрой вставки трекаемых ссылок в редакторе почтовых шаблонов
- Опциональный сервис превью-скриншотов учебных страниц (отдельный
  Docker-образ, не входит в основную установку — `docker compose --profile
  screenshots up -d`)
- Скрипт восстановления пароля администратора при утере
  (`npm run reset-admin-password`)
- Автоматическая проверка на недовыделенный LVM-том при установке —
  подсказывает команды для расширения, если физический диск больше, чем
  видит система

### Изменено

- Проект переименован: Security Awareness Platform → HowMuchIsTheFish.
  Репозиторий на GitHub переехал на новый URL (GitHub сохраняет редирект со
  старого). Новые Docker-образы в GHCR публикуются под именами
  `howmuchisthefish-backend`/`howmuchisthefish-frontend`; образы релиза
  v0.1.0 остаются в GHCR под прежним именем как исторический артефакт
- CORS открыт по умолчанию (любой адрес обращения проходит без ошибок) —
  ограничение конкретными адресами теперь осознанный шаг после установки,
  через `CORS_ALLOWED_ORIGINS`
- `install.sh`: автоматически ставит `docker-buildx` (устраняет
  предупреждение Docker Compose про Bake), сообщение об отсутствующем
  `.env` на первом прогоне больше не выглядит как ошибка установки,
  пользователь автоматически добавляется в группу `docker`
- Имя apt-пакета для docker compose исправлено на `docker-compose-v2`
  (`docker-compose-plugin` не существует в стандартных репозиториях)

### Исправлено

- Frontend-контейнер теперь сам проксирует `/api`, `/health`, `/lp`, `/t` на
  backend — вход в систему больше не требует обязательного внешнего
  reverse-proxy

## [0.1.0] — первый выпуск

Первая рабочая версия Security Awareness Platform — платформы для
контролируемых учебных фишинговых рассылок.

### Добавлено

- Управление сотрудниками: ручное создание, импорт из CSV с построчной
  валидацией, группы
- Почтовые шаблоны на основе MJML с переменными персонализации
- Учебные страницы с безопасным отслеживанием отправки формы — значения,
  введённые сотрудником, никогда не сохраняются на сервере
- Полный жизненный цикл кампании: создание, планирование, запуск, пауза,
  завершение
- SMTP-подключения с шифрованием пароля и проверочной отправкой
- Отслеживание событий: открытие письма, переход по ссылке, отправка формы,
  с классификацией подозрительных автоматических событий
- Аналитика по кампаниям, сотрудникам, группам с экспортом в CSV
- Установка одной командой (`scripts/install.sh`) на чистый Ubuntu/Debian
  сервер, два варианта публикации (встроенный HTTPS через Caddy или за
  внешним reverse proxy)
- Резервное копирование и восстановление с шифрованием архива
- Root-helper для безопасного обновления без прав Docker у контейнера
  приложения

### Известные ограничения

См. [docs/FEATURE_MATRIX.md](docs/FEATURE_MATRIX.md) — полный честный
список того, что реализовано и проверено, что реализовано, но не
проверено, и что отложено на будущие версии. В частности: визуальный
drag-n-drop редактор писем и страниц отложен (текстовый MJML/HTML-редактор
в этой версии), UI-поток входа через OIDC/SAML не реализован (переменные
окружения подключены, но без экрана входа), обновление через веб-интерфейс
не реализовано (есть командная строка).

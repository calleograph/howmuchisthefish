# Матрица функциональной полноты — версия 0.2.0

Легенда:
- **Готово, проверено** — реализовано и проверено реальным прогоном
  (ручной UI-тест через agent-browser и/или curl против настоящего backend
  в Docker-контейнерах), не только написан код
- **Готово, не проверено сквозным сценарием** — реализовано, прошло
  компиляцию/типизацию, но не проверено живым прогоном в этой сессии
- **Частично** — базовая версия есть, часть заявленного не реализована
- **Не реализовано** — отсутствует в 0.1.0, зафиксировано как задача на будущее

## Пользователи и сотрудники

| Возможность | Статус | Примечание |
|---|---|---|
| Ручное создание/редактирование сотрудника | Готово, проверено | CRUD проверен через API |
| Импорт из CSV с построчной валидацией | Готово, проверено | Проверено через реальный UI-upload: 2 created, 4 skipped с точными причинами |
| Группы, назначение в группы | Готово, проверено | Создание группы и bulk-assign проверены через UI |
| Вложенные группы (иерархия) | Готово, проверено | `parentGroupId`, рекурсивный подсчёт участников, защита от циклов — проверено через UI (создание родитель/потомок) и unit-тестами |
| Поиск/фильтрация | Готово, проверено | Поиск по email/имени на странице Сотрудники |
| Дополнительные настраиваемые поля сотрудников | Готово, проверено | Текст/число/да-нет/список значений, валидация типов при сохранении — проверено через UI |
| Массовые операции (кроме назначения в группу) | Не реализовано | Массовая деактивация, массовое удаление — нет в 0.2.0 |
| История изменений сотрудника | Частично | Пишется в БД (`EmployeeHistory`), нет отдельного экрана просмотра в UI |
| Массовое назначение в группу через UI | Не реализовано | Реализовано через API (`bulk/assign-group`), но без формы выбора нескольких сотрудников в интерфейсе |

| Безопасное отслеживание отправки формы | Готово, проверено | Критическая часть ТЗ — подтверждено: значения полей не достигают backend ни при каких условиях, проверено вручную включая попытку "взлома" (передача password в body → 400) |

| Каталог шаблонов страниц | Не реализовано | |

| Публикация по адресу `/lp/{slug}` | Готово, проверено | Проверено end-to-end с реальным трекингом |

| Клонирование сторонних сайтов | Намеренно не реализовано | Задание прямо исключило эту функцию донора из публичной версии (юридические и этические причины) |

## Кампании

| Возможность | Статус | Примечание |
|---|---|---|
| Создание кампании (шаблон+страница+SMTP+получатели) | Готово, проверено | Полный цикл через UI |
| Конечный автомат статусов | Готово, проверено | Запрещённые переходы (например FINISHED→RUNNING) отклоняются, проверено |
| Планирование (отложенный запуск) | Частично | Эндпоинт `schedule` есть, не проверен реальным прогоном с ожиданием времени |
| Запуск/пауза/возобновление/завершение | Готово, проверено | Весь цикл проверен через UI с реальной отправкой писем |
| Проверочная отправка | Готово, проверено | Эндпоинт `test/send` проверен |
| Таргетинг по группе (включая вложенные) | Готово, проверено | Таргетинг на родительскую группу рекурсивно разворачивает дочерние подгруппы — проверено через UI |
| Таргетинг по результатам прошлой кампании (сегмент) | Готово, проверено | Получатели по условию (открыли/кликнули/отправили форму/не открыли) из кампании-источника — проверено через UI |
| Таргетинг случайной выборкой | Готово, проверено | N случайных сотрудников, опционально из группы — проверено через UI |
| Ограничение по доменам получателей | Готово, не проверено сквозным сценарием | Код реализован, не проверялся вручную в этой сессии |
| Ограничение/контроль скорости отправки | Готово, проверено | `startAfter` в очереди pg-boss, явный UI-контрол в форме создания кампании (ранее был только неявным параметром) |
| Повторный запуск по правилам (периодичность) | Не реализовано | Кампания запускается один раз, автоматического повторения нет |
| История действий по кампании | Частично | Audit log есть на уровне БД, отдельного экрана истории кампании в UI нет |

## События и отслеживание

| Возможность | Статус | Примечание |
|---|---|---|
| email.sent / email.opened / link.clicked / form.submitted | Готово, проверено | Весь жизненный цикл проверен end-to-end с реальной SMTP-доставкой |
| reported_phishing («сообщил о фишинге») | Готово, проверено | Положительная метрика, отдельная ссылка `GET /t/report` (работает без JS) и переменная `{{reportPhishingUrl}}` в шаблонах — проверено через API |
| Классификация подозрительных автоматических событий | Готово, проверено | Эвристика по User-Agent реализована, протестирована на синтетических данных (не на реальном трафике сканеров) |

## Администрирование

| Возможность | Статус | Примечание |
|---|---|---|
| SMTP-подключения, тестовая отправка | Готово, проверено | Полный цикл с реальной доставкой через MailHog |
| Восстановление доступа при утере пароля администратора | Готово, проверено | `npm run reset-admin-password` (через SSH/docker compose exec) — проверено end-to-end: сброс, вход новым паролем, отказ по старому |
| Роли (ADMIN/EDITOR/VIEWER) | Готово, проверено | Проверено через guard-тесты и ручные запросы |
| Журналирование действий администраторов | Частично | Модель `AuditLog` в схеме, не используется активно в коде модулей (кроме неявного через события) |
| Диагностика системы | Частично | `/health` эндпоинт есть, отдельной страницы диагностики с деталями (время входа, сетевые проверки) нет |
| Резервное копирование из интерфейса | Не реализовано | `scripts/backup.sh`/`restore.sh` работают из командной строки, проверены реальным прогоном; кнопки в UI нет |
| Обновление из интерфейса | Частично | Root-helper (`scripts/root-helper/`) реализован и описан, но UI-экран "Обновление системы" с прогресс-баром не реализован в 0.1.0 — есть только командная строка |
| OIDC/SAML вход | Готово, не проверено сквозным сценарием | Переменные окружения и зависимости (`openid-client`) подключены, UI-поток входа через OIDC/SAML не реализован в контроллерах auth-модуля — это пробел, не "частично готово" |
| Срок хранения событий/журнала (retention) | Частично | Полноценной настраиваемой политики per-entity (ключи `retention.eventsDays`/`retention.auditLogDays` в `config-registry.ts`) по-прежнему нет, но добавлена ручная очистка по требованию из UI (Настройки → Обслуживание) с предпросмотром количества перед необратимым удалением — закрывает немедленную потребность без автоматизации |
| MFA | Не реализовано | Поле `mfaEnabled`/`mfaSecret` в схеме БД зарезервировано, логика включения/проверки MFA не реализована |

## Инфраструктура

|---|---|---|

| Root-helper автообновление | Готово, не проверено сквозным сценарием | Скрипты написаны и синтаксически проверены, реальный прогон apply_update.sh (требует второй версии продукта для отката) не выполнялся |

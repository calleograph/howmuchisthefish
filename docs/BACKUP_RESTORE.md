# Резервное копирование и восстановление

## Что входит в резервную копию

| Компонент | Источник |
|---|---|
| База данных | `pg_dump -Fc` (формат custom — компактнее, поддерживает выборочное восстановление) |
| Файловое хранилище | Docker volume `app-storage` (вложения, загруженные материалы) |
| Конфигурация | `.env` текущего развёртывания |

Резервная копия **зашифрована** (AES-256-CBC, пароль задаётся случайно при
создании и печатается один раз — нигде не сохраняется). Без пароля архив не
открыть. Так как `.env` входит в архив как есть, включая `APP_MASTER_KEY` —
зашифрованные поля в БД (SMTP-пароли) восстановятся корректно только если
восстановить тот же `.env` вместе с базой.

## Создание резервной копии

```bash
./scripts/backup.sh                    # автоматическая метка по времени
./scripts/backup.sh --label pre-change # своя метка
./scripts/backup.sh --keep 20          # хранить последние 20 копий (по умолчанию 10)
```

Копии сохраняются в `backups/*.tar.gz.enc`. **Сохраните пароль расшифровки
в отдельном защищённом месте** (менеджер паролей организации) — он
показывается только один раз в момент создания.

## Автоматическое резервное копирование

Через обновление из веб-интерфейса резервная копия создаётся автоматически
перед каждым применением миграций. Для планового копирования по расписанию
добавьте в cron хоста:

```bash
# Ежедневно в 03:00, хранить последние 14 копий
0 3 * * * cd /opt/howmuchisthefish && ./scripts/backup.sh --keep 14 >> /var/log/sap-backup.log 2>&1
```

## Восстановление

```bash
./scripts/restore.sh backups/2026-01-15-120000.tar.gz.enc
```

Скрипт:
1. Запрашивает подтверждение именем проекта (защита от случайного запуска
   не на том сервере)
2. Запрашивает пароль расшифровки
3. **Создаёт страховочную копию текущего состояния** (`pre-restore-*`) —
   если восстановление окажется ошибкой, можно откатиться и к нему
4. Останавливает backend, заменяет БД и хранилище, применяет миграции
   (на случай восстановления со старой версии схемы), запускает всё заново

Для автоматизации (например из root-helper) используйте `--force`, чтобы
пропустить интерактивное подтверждение — но тогда проверка имени проекта
не выполняется, убедитесь, что скрипт запускается на правильном сервере.

## Срок хранения и персональные данные

Резервные копии содержат персональные данные сотрудников (email, имя,
отдел) и историю событий кампаний. Определите политику хранения в
соответствии с требованиями вашей организации — `--keep N` ограничивает
количество хранимых архивов, но не заменяет организационную политику
удаления устаревших данных. Срок хранения событий кампаний в самой БД
настраивается отдельно в **Настройки → Хранение данных**.

## Проверка восстановления

Рекомендуется периодически проверять, что резервная копия реально
восстанавливается — на тестовом сервере, не на продакшене:

```bash
# На отдельном тестовом сервере с чистой установкой
./scripts/install.sh --dry-run   # убедиться, что окружение готово
./scripts/restore.sh <архив> --force
curl -f http://localhost:3000/health
```

# Руководство администратора

## Первый вход

После установки (см. [INSTALL.md](INSTALL.md)) создайте администратора:

```bash
cd deployment
docker compose exec backend npm run seed
```

Войдите по адресу вашего домена с указанным email/паролем.

## Восстановление доступа, если пароль администратора утерян

Встроенного восстановления пароля по почте нет (система специально не
отправляет писем сама себе — см. [SECURITY.md](SECURITY.md)). Если пароль
администратора утерян, а SSH-доступ к серверу есть, сбросьте его напрямую:

```bash
cd deployment
docker compose exec \
  -e RESET_EMAIL=admin@example.local \
  -e RESET_PASSWORD='НовыйНадёжныйПароль123!' \
  backend npm run reset-admin-password
```

Скрипт требует, чтобы пользователь с таким email уже существовал (иначе
используйте `npm run seed` для создания первого администратора) и чтобы
новый пароль был не короче 8 символов.

## Типовой сценарий: первая учебная кампания

### 1. Загрузите сотрудников

**Сотрудники → Импорт из CSV**. Формат файла:

```csv
email,firstName,lastName,department,position
ivan.petrov@example.com,Иван,Петров,ИТ,Разработчик
```

Колонки `email`, `firstName`, `lastName` обязательны, `department` и
`position` — опционально. После импорта система покажет, сколько записей
создано/обновлено и какие строки пропущены с указанием причины (неверный
email, дубликат, пустое поле).

### 2. Создайте группу

**Сотрудники → Новая группа** — например "Отдел продаж". Назначьте в неё
нужных сотрудников.

### 3. Создайте почтовый шаблон

**Шаблоны писем → Новый шаблон**. Используйте переменные `{{firstName}}`,
`{{lastName}}` для персонализации и `{{landingPageUrl}}` для ссылки на
учебную страницу. Формат — [MJML](https://mjml.io/) (гарантирует корректное
отображение в разных почтовых клиентах).

### 4. Создайте учебную страницу

**Учебные страницы → Новая страница**. Укажите HTML страницы и включите
"отслеживание формы", если хотите фиксировать факт отправки данных. Адрес
страницы (`slug`) станет частью короткой публичной ссылки `/lp/{slug}`.

### 5. Настройте SMTP

**Настройки → Новое подключение** — данные вашего SMTP-релея (см.
[SMTP_SETUP.md](SMTP_SETUP.md)). Проверьте тестовой отправкой перед
использованием в кампании.

### 6. Создайте и запустите кампанию

**Кампании → Новая кампания** — выберите шаблон, страницу, SMTP-подключение
и группу получателей. После создания кампания в статусе "Черновик" —
нажмите "Запустить".

### 7. Следите за результатами

На странице кампании видна статистика в реальном времени: отправлено,
открыто, переходов по ссылке, отправлено форм. Экспортируйте детальный
список событий в CSV для дальнейшего анализа.

## Роли

| Роль | Права |
|---|---|
| ADMIN | Полный доступ, включая SMTP-подключения |
| EDITOR | Создание и управление кампаниями, шаблонами, страницами, сотрудниками — без доступа к SMTP-настройкам |
| VIEWER | Только просмотр |

## Диагностика

```bash
cd deployment
docker compose ps              # статус всех сервисов
docker compose logs -f backend # логи backend в реальном времени
curl -f https://ваш-домен/health
```

Если backend не проходит healthcheck:

```bash
docker compose logs backend --tail 100
```

Частые причины: неверный `DATABASE_URL` в `.env`, PostgreSQL ещё не готов
(подождите, `depends_on: condition: service_healthy` должен дождаться
сам), незаполненные секреты (`JWT_SECRET`/`APP_MASTER_KEY` всё ещё
`CHANGE_ME_*`).

## Срок хранения данных

В версии 0.1.0 автоматическое удаление устаревших событий/журнала по
сроку хранения **не реализовано** — это отложено на будущую версию (см.
[FEATURE_MATRIX.md](FEATURE_MATRIX.md)). Если вашей организации требуется
соблюдать определённый срок хранения персональных данных сотрудников,
удаляйте устаревшие записи вручную через прямые SQL-запросы к БД или
дождитесь реализации этой функции в следующих релизах.

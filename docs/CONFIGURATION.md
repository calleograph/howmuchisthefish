# Конфигурация

Все настройки развёртывания — в `deployment/.env` (копия
`deployment/.env.example`). Backend читает те же значения как переменные
окружения контейнера — отдельного файла конфигурации для приложения нет.

## Обязательные переменные

| Переменная | Назначение |
|---|---|
| `COMPOSE_PROJECT_NAME` | Имя проекта Docker Compose (например `sap`) — изолирует тома/сети при нескольких инсталляциях на одном сервере |
| `DOMAIN` | Домен для встроенного HTTPS (Caddy/Let's Encrypt) |
| `PUBLIC_BASE_URL` | Публичный адрес приложения (`https://домен`) — используется в ссылках писем и трекинг-пикселе |
| `DB_PASSWORD` | Пароль PostgreSQL — генерируется установщиком |
| `JWT_SECRET` | Ключ подписи JWT-токенов — генерируется установщиком |
| `APP_MASTER_KEY` | Ключ шифрования секретов в БД (SMTP-пароли) — генерируется установщиком. **Храните отдельно от резервных копий**: без него зашифрованные значения не восстановить |

## Опциональные переменные

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `CORS_ALLOWED_ORIGINS` | — (открыто для всех) | Список разрешённых адресов через запятую — см. раздел ниже |
| `LOG_LEVEL` | `info` | Уровень логирования backend (`debug`/`info`/`warn`/`error`) |
| `BACKEND_PORT` | `3000` | Порт backend на loopback (только режим `external-proxy`) |
| `FRONTEND_PORT` | `8080` | Порт frontend на loopback (только режим `external-proxy`) |
| `OIDC_ENABLED` | `false` | Включить вход через OIDC |
| `OIDC_ISSUER_URL` | — | URL OIDC-провайдера |
| `OIDC_CLIENT_ID` / `OIDC_CLIENT_SECRET` | — | Данные OIDC-клиента |
| `OIDC_REDIRECT_URI` | — | Redirect URI, зарегистрированный у провайдера |
| `SAML_ENABLED` | `false` | Включить вход через SAML (legacy-путь) |
| `SAML_IDP_METADATA_URL` | — | URL метаданных SAML IdP |
| `SAML_ENTITY_ID` | — | Entity ID приложения у SAML IdP |
| `BACKEND_IMAGE` / `FRONTEND_IMAGE` | — | Явный тег образа из GHCR (для установки готового релиза вместо сборки из исходников) |

## CORS: ограничение адресов доступа (сделать после первичной настройки)

По умолчанию `CORS_ALLOWED_ORIGINS` пуст, и backend принимает запросы
браузера с любого адреса — так систему можно сразу открыть и по домену,
и по IP в локальной сети, и через несколько reverse-proxy одновременно, не
разбираясь заранее со списком адресов. Это осознанный компромисс ради
простого первого входа, не постоянная рекомендация.

Когда адреса доступа к системе станут известны и стабильны, ограничьте их
явным списком — это не даёт браузеру отправлять авторизованные запросы
с посторонних сайтов от имени залогиненного администратора:

```bash
cd deployment
nano .env
# CORS_ALLOWED_ORIGINS=https://sap.example,http://192.168.1.50:8080
docker compose up -d backend
```

## Секреты в базе данных

Отдельные от `.env` секреты (SMTP-пароли, OIDC client secret, сохранённые
через веб-интерфейс) хранятся в БД зашифрованными `APP_MASTER_KEY`
(AES-256-GCM) — в открытом виде не возвращаются ни через API, ни в
резервных копиях. Подробности политики переноса каждого поля — в
[BACKUP_RESTORE.md](BACKUP_RESTORE.md).

## Изменение конфигурации после установки

```bash
cd deployment
nano .env
docker compose up -d   # пересоздаёт изменившиеся контейнеры
```

Изменение `JWT_SECRET` разлогинит всех пользователей (токены станут
невалидны) — это безопасно, но предупредите сотрудников. Изменение
`APP_MASTER_KEY` **сделает невосстановимыми уже сохранённые зашифрованные
секреты** (SMTP-пароли нужно будет ввести заново) — меняйте только при
понимании последствий.

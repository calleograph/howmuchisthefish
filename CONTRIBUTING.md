# Участие в разработке

Спасибо за интерес к проекту. Этот документ описывает, как предложить
изменения.

## Сообщить об ошибке

Откройте issue с:
- Версией продукта (`cat VERSION` или футер интерфейса)
- Шагами для воспроизведения
- Ожидаемым и реальным поведением
- Логами (`docker compose logs backend` — **проверьте, что в логах нет
  секретов/персональных данных вашей организации перед публикацией**)

## Сообщить об уязвимости безопасности

**Не создавайте публичный issue.** См. раздел "Сообщить об уязвимости" в
[docs/SECURITY.md](docs/SECURITY.md).

## Предложить изменение

1. Форкните репозиторий, создайте ветку от `main`
2. Внесите изменения
3. Для backend: `cd backend && npm run build && npm run test`
4. Для frontend: `cd frontend && npm run build`
5. Откройте Pull Request с описанием, что и зачем меняется

## Требования к коду

- TypeScript strict-режим — не отключайте проверки точечными `any`/`@ts-ignore` без явной причины в комментарии
- Backend: модуль = своя директория в `src/modules/`, со своими DTO,
  сервисом, контроллером, модулем NestJS
- Новое поле в Prisma-схеме с пометкой `@policy:*` — добавьте запись в
  `config-registry.ts` (тест `config-registry.spec.ts` проверяет это
  автоматически и упадёт, если забыть)
- Не добавляйте зависимость ради нескольких строк — сначала проверьте, есть
  ли уже нужное в составе NestJS/React/используемых библиотек

## Синтетические данные

Любые тестовые данные, примеры, скриншоты в Pull Request должны быть
полностью синтетическими — без реальных email, имён, доменов конкретной
организации. CI проверяет это сканером по белому списку.
